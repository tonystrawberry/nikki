## TL;DR

講座ではこの章は任意扱いで、claude.ai そのものの紹介になっている。役に立つのは、適切なモデルを選ぶこと、コンテキストを **Projects** と**カスタム指示**に入れること、**メモリ**を有効にすること、**アーティファクト**を作ること、シンプルなプロンプトの公式を使うこと。

## プラン

| プラン | 料金 | 対象 |
|---|---|---|
| Free | $0 | お試し：上限が厳しく、Projects なし |
| **Pro** | 月 $20（年払いなら月 $17） | 日常的に使う大半の人：Projects 無制限、Claude Code、Cowork |
| Max | 月 $100 から | ヘビーユーザー：上限が高い、新機能の先行利用、優先アクセス |
| Team / Enterprise / API | — | 組織と開発者 |

## どのモデルを使う？

- **Haiku**：最速で最安。簡単な Q&A、大量処理やリアルタイムのタスク。
- **Sonnet**：デフォルトで、バランスが最も良い。執筆、調査、コード、ドキュメント。タスクの約 90%。
- **Opus**：深い推論。結果が本当に重要なときに。

## LLM の仕組みをざっくり

膨大なテキストで学習したニューラルネットワーク。**最も役立つ次のトークンを予測する**のであって、「理解」したり調べたりしているわけではない。アップロードしたファイルも含め、送ったものはすべて限られた**コンテキストウィンドウ**の中のトークンになる。

## カスタム指示

**Settings → General → instructions/preferences** はすべてのチャットに適用される。例：「明確で構造化された回答をしてください。実用的なユースケースを重視してください。」

## Projects

Project は、**ファイル**、**指示**、**メモリ**を共有するチャットのフォルダ。たとえばガイド類をまとめた「Marketing」プロジェクトなど。既存のチャットは ⋯ → *Add to project* でプロジェクトに移せる。

指示が適用されているかの簡単なテスト：「すべての回答の最後に `[test]` を付けて」と加える。

## メモリ

**Settings → Capabilities → Memory** には2つのオプションがある：*過去のチャットを検索・参照する* と *チャット履歴からメモリを生成する*。どちらもチャットとプロジェクトの両方が対象。仕組みは検索（RAG）に近く、Claude が調べるノートのようなもの。まっさらな状態にしたいときは新しいチャットを始める。

## アーティファクト

Claude がチャット内で直接作るインタラクティブなもの：ダッシュボード、Web アプリ、ゲーム、フラッシュカード、変換ツール。デモは SaaS の KPI ダッシュボード（売上、成長率、ファネル）と「プロンプト生成」アプリで、どちらも約2回のプロンプトで作ってから手直しした。

## プロンプトの公式

**役割 + タスク + コンテキスト + 形式 = 結果**

```text
シニアコンテンツマーケターとして振る舞ってください。      # 役割
<topic> について 1,200 字のブログ記事を段階的に書いてください： # タスク
構成、導入、3つのセクション、CTA。
私のトーンに合わせるため、過去の記事を3本渡します：<files>。 # コンテキスト
H2 見出しつきのドキュメントアーティファクトとして返してください。 # 形式
```

長いものは、まず構成を頼んでから各パートを膨らませる。繰り返す作業は代わりに **Skill** にする。

## ファイル、画像認識、音声

アップロードした PDF、CSV、DOCX は**テキストに変換されてトークン化**され、長いメッセージと同じようにコンテキストに入る。スキャンした PDF は画像であり、非常に大きなファイルはコンテキストウィンドウを超えると**切り詰められる**ことがある。Claude は画像も読め、音声入力にも対応している。
